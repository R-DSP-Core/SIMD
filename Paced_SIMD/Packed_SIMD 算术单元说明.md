# Packed-SIMD 算术单元说明

本目录实现面向 packed-SIMD 的 32 位整数加法器与乘法器，通过 `SIMDMode` 信号选择数据通路宽度。

## 公共约定


| `SIMDMode`  | 含义       |
| ----------- | -------- |
| `00` / `11` | 1×32 bit |
| `01`        | 4×8 bit  |
| `10`        | 2×16 bit |


操作数与结果均为 32 位字。在 packed 模式下，各 lane 相互独立运算，lane 之间不传播进位。

在仓库的 `build.sbt` 中把 pack`_simd` 加入 Compile 源码路径后可用进行功能测试：

```bash
sbt "testOnly PackSimdSpec"
```

## 文件组成


| 文件                 | 内容                                       |
| ------------------ | ---------------------------------------- |
| `adder.scala`      | `BLevelPAdder32_SIMD`：并行前缀加法器，支持可选的有符号饱和 |
| `multiplier.scala` | `BLevelPMul32_SIMD`：基于 8×8 Booth 的嵌套乘法阵列 |

## 加法器 `BLevelPAdder32_SIMD`



### 功能

对 `src1` 与 `src2` 执行加法。`cin` 在每个 lane 的起始位注入，用于实现 packed 减法（对减数按位取反后加一）。运算结果按 lane 独立回绕；`sat=1` 时对各 lane 执行有符号饱和。

### 接口


| 信号              | 方向  | 说明                                  |
| --------------- | --- | ----------------------------------- |
| `src1` / `src2` | 输入  | 32 位操作数                             |
| `SIMDMode`      | 输入  | 含义见上表                               |
| `cin`           | 输入  | 进位输入，注入到各 lane 的起始位（用于 packed 减法）   |
| `sat`           | 输入  | 有符号饱和使能                             |
| `res`           | 输出  | 32 位和                               |
| `cout`          | 输出  | 取 32 位加法模式下的最高位进位；SIMD 模式下该信号语义尚未定义 |




### 结构实现

- 以 4 bit 为一组实现 Brent–Kung 并行前缀进位（`BLevelCarry4`）。
- 在 8 bit / 16 bit lane 边界切断组间进位，并在求和进位向量上清除跨 lane 的进位位后，将 `cin` 写回各 lane 起始位。
- 有符号饱和（`SatSIMD`）依据两个操作数与和的符号位判定正溢出与负溢出。

## 乘法器 `BLevelPMul32_SIMD`



### 功能

对各 lane 输出有符号整数乘积的**低 N 位**（N 为该 lane 宽度）。

依据：对同一套 N 位操作数位型，将其解释为有符号数或无符号数后再相乘，所得乘积的低 N 位相同；完整 2N 位乘积的高半一般不同。因此本模块用无符号乘法实现即可得到与有符号乘法一致的低半结果。内部 8×8 按无符号乘法实现，部分积做零扩展后对齐累加（不做符号扩展）。

当前版本不提供饱和、高半乘积（`MULH`）以及无符号乘法的实现。

### 接口


| 信号              | 方向  | 说明                                    |
| --------------- | --- | ------------------------------------- |
| `src1` / `src2` | 输入  | 32 位操作数                               |
| `SIMDMode`      | 输入  | 含义见上表                                 |
| `res`           | 输出  | 各 lane 乘积低半结果拼接而成的 32 位结果（相对输入延迟 2 拍） |




### 结构实现

1. **子单元** `Mul8`：无符号 8×8 radix-4 Booth 乘法器。5 组部分积经 3:2 CSA 压缩后，由 16 位前缀加法器完成求和；负 Booth 编码对应的已对齐部分积按位取反，并在 bit0 加一。
2. **4×4 阵列**：将每个操作数拆分为 4 个 8 bit limb，得到 16 个部分积 P_{ij} = A_i × B_j；各项零扩展至 64 bit 后左移 8(i+j) 位完成对齐。
3. **按模式屏蔽交叉项**：
  - 1×32：保留全部 16 项；
  - 2×16：保留两个 2×2 子块；
  - 4×8：仅保留对角线项，结果直接取各对角线叶子乘积的低 8 bit 拼接（不从 64 bit 累加结果中切片）。
4. **累加与流水**：启用项经 64 bit CSA 树压缩，末级采用本地 64 位前缀加法器（复用 `BLevelCarry4`）。
  - 2×16：`res = sum[47:32] ## sum[15:0]`；
  - 1×32：`res = sum[31:0]`。
   流水切级与主树乘法器保持对应：部分乘积对齐后进入第一级寄存器，CSA 压缩完成后进入第二级寄存器，随后执行前缀加法与结果选择。总延迟为 2 拍。

在 2×16 模式下，每个 2×2 子块对应一次完整的无符号 16×16→32 乘法，其结果分别占据互不相交的 `sum[31:0]` 与 `sum[63:32]`，从而保证 lane 之间的隔离。

## 尚未覆盖的范围

- 加法器的 `cout`、乘法器的高半结果与饱和功能，均尚未作为正式接口。
- 乘法器的流水使能目前恒为有效；若后续需要与除法器或其他部件共享时序，可引入类似 `divBusy` 的门控信号。
