# SIMD 纯计算核接口说明

## 1. 概述

本目录实现一组面向向量流计算的**纯计算部件**，定位类似于 `ALU.scala`：硬件只负责运算与本地累加寄存器（VReg）的维护，不负责指令派发、多路完成结果的合并，也不负责结果的搬运。

计算核对外引出两个独立的运算端口（Add 口与 Mul 口），并提供供外部直接访问的 VReg 端口。Add 与 Mul 各自保留独立的 `done` 与 `result`，顶层**不会**把两路完成信号或结果总线做逻辑或合并。

---

## 2. 文件组成


| 文件                           | 内容                                                           |
| ---------------------------- | ------------------------------------------------------------ |
| `SimdArithmetic.scala`       | 本地的 32/64 位并行前缀加法器，以及 Booth/Wallace 结构的有符号乘法器（对外只输出乘积低 32 位） |
| `VectorStreamPipeline.scala` | 八路并行的加法流水线 `SimdAddPipe`，以及乘法/外积乘加流水线 `SimdMulPipe`          |
| `VecRegfile.scala`           | 操作码常量 `SimdOp`，以及单份架构态的 8 bank × 8 lane × 32 bit 向量累加寄存器堆    |
| `SimdFu.scala`               | 顶层模块 `SimdCompute`：分别引出 Add 口与 Mul 口，并提供供外部访问的 VReg 端口       |


---



## 3. 顶层结构（`SimdCompute`）

外部逻辑（例如未来的 VLIW slot）分别驱动加法口和乘法口；本地 VReg 既供 OMAC 累加使用，也允许外部直接读出或清零。`flush` 只冲刷两条流水线里尚未完成的操作，**不会**清除 VReg 中已经写入的数据。

```text
          add.valid / srcA / srcB  --> AddPipe --> add.result / add.done
外部接口  { mul.valid / op / ...   --> MulPipe --> mul.result / mul.done
          vreg.rbank / clearAll   <--> VReg   <--- OMAC 写回
          flush --> 只冲刷管线在途操作，不清空 VReg
```
---



## 4. 端口说明



### 4.1 加法口 `add`


| 信号                | 含义                                              |
| ----------------- | ----------------------------------------------- |
| `valid` / `stall` | 输入有效与反压握手。加法流水线当前不会产生反压，因此 `stall` 恒为 0。        |
| `srcA` / `srcB`   | 两个长度为 8、元素宽度为 32 bit 的输入向量。                     |
| `result` / `done` | 运算结果与完成指示。操作被接受后，第 2 个周期拉高 `done`，并给出 `result`。 |




### 4.2 乘法/乘加口 `mul`


| 信号                                           | 含义                                                                                                    |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `op`                                         | 本拍要执行的操作，只允许取 `MUL` 或 `OMAC`。                                                                         |
| `bank`                                       | OMAC 写入的 VReg bank 编号；对普通 MUL 无意义。                                                                    |
| `dstToVReg`                                  | 仅对 MUL 有意义：为 1 时，除了给出 `result`，还会把结果写入 VReg 的 bank 0。                                                 |
| `stall`                                      | 反压信号。若上一拍刚接受了 OMAC，而本拍紧接着要发 MUL，则 `stall` 为 1，用于避免写回时序冲突。                                             |
| `result` / `done` / `writeVreg` / `doneBank` | 结果与完成侧信息。MUL 在接受后第 5 个周期完成；OMAC 在接受后第 6 个周期完成。`writeVreg` 表示本拍正在写 VReg；`doneBank` 给出 OMAC 实际写入的 bank。 |




### 4.3 VReg 外端口 `vreg`


| 信号                | 含义                                                                     |
| ----------------- | ---------------------------------------------------------------------- |
| `rbank` / `rdata` | 外部读端口。外部可以把某个 bank 的内容读出后写入 FIFO，从而自行实现原先的 VREG2FIFO 语义。               |
| `clearAll`        | 外部清零请求。拉高后，全部 bank 在时钟边沿被清零，用于自行实现原先的 VCLEAR 语义。                       |
| `readingBusy`     | 读口占用指示。OMAC 处于 EX4 累加读阶段时该信号为 1；此时外部不应再依赖自己给出的 `rbank`，因为读口正被 OMAC 使用。 |




### 4.4 `flush`

`flush` 只会作废 Add 管线与 Mul 管线中**尚未写回的在途操作**，不会清空 VReg 里已经存在的累加结果。

---



## 5. 操作码（`SimdOp`）


| 编码值 | 名称   | 语义                                                                                   |
| --- | ---- | ------------------------------------------------------------------------------------ |
| 0   | ADD  | 通过 `add` 口发起。对 8 个 lane 分别做 32 位加法，结果按模 `2^32` 回绕。                                   |
| 1   | MUL  | 通过 `mul` 口发起。对 8 个 lane 分别做有符号 32×32 乘法，只保留乘积的低 32 位。                                |
| 2   | OMAC | 通过 `mul` 口发起。将 `srcA(0)` 广播到全部 lane，与 `srcB` 对应 lane 相乘后，再累加到 `VReg[bank]` 的对应 lane。 |


---

## 6. 移植到新处理器时的流水线替换

`VectorStreamPipeline.scala` 与 `SimdFu.scala` 只是本目录自带的一套参考流水：加法为输入打拍后组合运算再打拍写出，乘法按 `SimdMul32` 的两级内部延迟对齐，并处理 OMAC 累加、同 bank 旁路、写口反压和 VReg 读口占用。它们**不是**运算器规格的一部分。

在新处理器中自行搭建流水线时，可以只保留 `SimdArithmetic.scala`（标量 32 位加法器 / 乘法器，由新流水按 lane 例化）和 `VecRegfile.scala`（若仍做 OMAC 累加），用本机的发射、冲刷、反压和写回控制替换上述两个文件。替换时需自行对齐乘法器内部延迟，并视是否保留 OMAC 决定是否实现广播、旁路与 VReg 端口仲裁。`dstToVReg`、加法延迟拍数等也由新流水自行约定。

此流水线遵循以下调用约定

1. **读 VReg 再写入 FIFO**：应先等待 `vreg.readingBusy` 为 0，再给出目标 `rbank`，然后采样 `rdata` 并写入 FIFO。
2. **清空全部 VReg**：应拉高 `vreg.clearAll`，并避免与同一拍正在进行的 OMAC 或 MUL 写 VReg 冲突。
3. **双端口并发**：Add 口与 Mul 口可以同时有在途操作。调用方应分别观察各自的 `done` 与 `result`，不要假定顶层会把两路完成事件合并成一次写回。若要把运算结果写入 FIFO，应在观测到 `add.done`，或观测到 `mul.done && !mul.writeVreg` 时，自行决定是否写入对应的 `result`。
4. **反压保持**：当某一端口的 `stall` 为 1 时，调用方必须保持该端口本拍的输入不变，直到该操作真正被接受为止。
